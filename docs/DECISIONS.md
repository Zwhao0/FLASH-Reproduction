## 正式API约束与证据边界

U15 的额外算术边界：§3.3.1（33/49）给出写入50–200ns、AllReduce 100us–10ms，按这些范围独立计算的占比可从0.0005%到0.2%，不能推出该段所述通用 `<0.001%` 上界。这是范围推导，不是实际开销测量。图文120ms/3ms的例子也未证明属于同一次观测，先保留差异，不据此裁定哪个值错误。

NCCL 官方 Group 文档说明：组内调用可能尚未入stream，嵌套组要等最外层结束；Group可涉及不同stream/device，非阻塞comm还需要处理尚未完成入队的状态。这是 U06/U11 的验证约束，不能直接证明论文环境下的实际行为。[NCCL Group说明](https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/usage/groups.html)

CUDA Event记录指定stream当时已有的工作；同步等待所捕获工作完成；elapsed time可能受其他操作调度影响。因此不能未经实际时序验证将Event总时长称为单个collective的纯kernel执行时间。[CUDA Event正式文档](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__EVENT.html)

这两份当前文档分别标示 NCCL 2.32.3、CUDA Runtime 13.4，均不是论文环境的运行验证。Rbeast公开说明为贝叶斯时序分解与变点检测，不能仅凭名称把其输出认定为论文所写的在线run-length后验。[Rbeast官方仓库](https://github.com/zhaokg/Rbeast)
