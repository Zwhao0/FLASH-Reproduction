## 可并行任务及最早闭环

P1 中，论文与作者澄清、独立样例推导、GitHub 身份/保护配置方案可以并行。关键判定未冻结时，可以准备记录字段、序列号/epoch 草案及脱敏证据格式，但不能把草案当最终接口或开展 P2 算法实现。

P2 在相应契约获批后可并行推进：Probe 记录协议的离线生产/消费验证；控制平面的 Redis 模拟与状态转换；框架迭代和 parallel states 适配的假数据验证；独立算法反例复核。实现者与验收者分开。任何改变观测对象、时序、阈值或真实测试预期的修复先回到科学审核。

优先把 P2 的接口接到 P3 的一个真实通信场景，先证明记录、状态、计时和身份能闭环，再扩大拓扑和故障矩阵。P3 不等待 P5 的所有 MoE 支持；P3 的结果也不能用于宣称 MoE 或一般通信拥塞已验证。部署前先用未来获批的目标环境清单核对 ABI、动态链接、共享内存原子/布局、Redis 连接和 NCCL Group/stream 能力；不读取当前服务器配置来推定已具备条件。

## 验收口径与恢复

每轮记录需求 ID、对象 commit、环境的最小非敏感摘要、命令、退出码、预期与实际结果、证据路径，以及 PASS/FAIL/NOT_RUN/INCONCLUSIVE。定位输出要包含候选标签/组/rank 与原始支持统计，不能只留下一个 rank。精确率/召回率须冻结真值、样本集合、分母、多故障/多候选与无法判定的计数方式。

失败保留，不重写 golden、不删除反例。两次有实质差异的修复仍失败时交由独立智能体诊断；需要科学裁定则停止对应机制、继续其他已授权且无依赖任务。未授权阶段只保留计划，不启动实现或实验。

1. ChatGPT 逐项审核 OPEN 决策，尤其 BOCD/Rbeast 与 Group/Event 的语义；Owner 明确接受的方案和暂缓项。

4. 只有未来具备单独具体授权才准备 P3 的服务器最小闭环。提供连接信息本身不构成运行权限。
